# Fresh PowerDNS V3 prestart inverse on disposable Debian (2026-09-28)

Scope: D-025 invariants 1–4 and P0.4/P0.5. This is one **fresh, uninitialized** Debian 13 PowerDNS-primary operation, cut at the fsynced `target-enable-intent`/`after-write` boundary before the candidate database was renamed or `pdns.service` started. The fixture ID was `pdns-switch__intent__after-write__paired-primary__peer-reachable`. The native tagged Agent test is `TestNativeFreshPDNSPrimaryV3PrestartInverse`; the test binary SHA-256 was `74c3ad29a7924b027649c01928a4ce39668a73f0e2a65214684fbcbe303a9f1f`. The independently installed recovery runtime's `runtime.manifest` SHA-256 was `2fde63ceae5359f7b28133710b8564bcce1cf7071a7cdbe89d7bde164068765f`. Neither installed Frankfurt nor Boston was touched.

The first fresh attempt (`243e3f4a898f7c24d56e179c822a6c17`) stopped at the intended cut, but owner recovery refused before effects: `prove DNS target cgroup empty: DNS service cgroup identity differs from the fixed system slice`. Debian systemd reports blank `Slice` and `ControlGroup` for a masked inactive service. The cgroup proof now accepts both blank fields only when the fixed native cgroup path is absent; a present or unexpected group still fails closed. [Unit observations](attempt1-units.txt) are retained. No rollback success is claimed for this attempt.

The second fresh attempt (`7fca874bc11a9282708489be64a460f9`) reached the same cut, but owner recovery refused before effects: `another DNS listener occupies port 53 while BIND is stopped`. Only Debian's local `systemd-resolved` stub was listening. The protected inverse now uses the shared canonical listener parser and excludes only loopback/link-local rows; a public, wildcard or malformed port-53 row still blocks rollback. [Unit observations](attempt2-units.txt) are retained. No rollback success is claimed for this attempt.

The third clean attempt, request `d3179958e0c9b3014f0a40dd146d2211`, recorded a transient [systemd process death](systemd-cut.txt) with `Result=signal`, `ExecMainCode=2`, `ExecMainStatus=9` (SIGKILL). A separate, installed, manifest-verified owner command `recover-dns-pdns-fresh-prestart --request-id d3179958e0c9b3014f0a40dd146d2211` returned success: `The exact fresh PowerDNS prestart operation was restored and its rollback verdict recorded.` The command did not require the Agent or Panel. It left PowerDNS inactive/masked, removed the candidate database and active V3 journal/state, and recorded `dns_engine_switch_rolled_back_by_owner_recovery` in the [terminal ledger](terminal-ledger.json). The original switch job therefore remains `failed`; that is the correct historical outcome, not a failed rollback. The PowerDNS package ownership receipt remains because this inverse does not uninstall packages.

After a reboot with Agent and Panel disabled, the [native service record](post-reboot-units.txt) shows `pdns.service` remained inactive/masked (`MainPID=0`), both management units remained inactive/disabled, `/var/lib/powerdns/pdns.sqlite3` remained absent, and only the install-ownership receipt plus terminal ledger remained in the private state directory. Since the source was uninitialized, no DNS authority was expected after rollback. The exact-request `dns-switch-status --quiesced` command could not run after reboot because its read-only `AcquireExisting` path requires the volatile `/run/celikpanel/service-mutation.lock`; this owner-guidance gap was observed in the native trial. A later source change adds `dns-switch-status --request-id` for a journal-free terminal ledger receipt without the volatile lock; focused tests and [a separate disposable Debian reboot check](../pdns-v3-recorded-status-20260928/README.md) with this exact canonical ledger passed. That check did not replay the producer or inverse. It did not mutate state to recreate the lock.

This closes **one native prestart inverse cell**. It does not prove a later cut, poststart/committed inverse, owner-edit race, an existing BIND-to-PowerDNS migration, setup/RPC admission, full paired DNS lifecycle, or automatic installed-panel update recovery. No release was published or installed. P0.4/P0.5 and the public PowerDNS-primary gate remain open.
