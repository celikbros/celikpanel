# Owner-operated BIND secondary inspector enrollment (2026-09-28)

Scope: D-025 invariants 1–3, P0.4/P0.5. A disposable Debian 13 primary at `192.0.2.10` and panel-free Arch BIND secondary at `192.0.2.11` exercised the new local `dns-peer-enroll` source command. No installed server was changed, no release was published, and the public DNS-pair gate stayed closed. The native BIND secondary was already configured for catalog transfer; its `named.service` was active. This trial tested optional deletion-inspector enrollment, not ordinary AXFR setup.

The primary created a root-only Ed25519 credential (`a0bbdce167170969c7d24301d1c7ba64`), exposed only its public key to the secondary, and pinned the secondary's independently read Ed25519 host-key SHA-256 (`c34a4505416236c5b460c2f6df51ee44eaf055d3e05ae319ee1d402febda4c47`) in canonical `celikpanel-dns-peer-inspection/v1` record `b28df821f5d836e3f0f2c22b3f1515b7`. The secondary installed a locked `celikpeer` account, root-owned inspector/policy, fixed-command SSH Match rule, source-address-bound public key and SSH configuration receipt. `secondary-status` returned **configured**, not proof of a live DNS response. During native setup, the first attempts stopped safely on Go file-owner type, OpenSSH Include ordering, effective-setting case, `AuthorizedKeysCommand none`, and authorized-key traversal errors. Each was corrected in source before the final fresh secondary install. These failures show why a local policy check alone is insufficient.

With the final binary (SHA-256 `80a97eafc7b5cd0ae636a3b1a4dc08768840c24e45379da785040849fd48a902`), Debian SSH authenticated as `celikpeer` using the prepared key. The fixed inspector returned `native BIND peer observation unavailable` for an empty request, as expected: the fixture had no transferred catalog and no valid deletion challenge. An attempted `id` command exited 1 and produced no `uid` output. Effective `sshd -T` for the account showed `AuthenticationMethods publickey`, `PasswordAuthentication no`, `AuthorizedKeysCommand /usr/bin/false`, `ForceCommand /usr/local/libexec/celikpanel-bind-peer-inspect-wrapper`, `DisableForwarding yes`, `PermitTTY no`, and `PubkeyAcceptedAlgorithms ssh-ed25519`.

After rebooting Arch, `named.service` was `active`, `secondary-status` remained `configured`, and the prepared key again authenticated to the fixed inspector. Explicit `secondary-revoke` removed the authorization; the same SSH attempt then returned `Permission denied (publickey)`, while `named.service` stayed active. Primary `primary-revoke` archived the exact enrollment record and `primary-status` returned `disabled`. The test SSH client used `StrictHostKeyChecking=no` only to diagnose the local channel; this trial did **not** exercise the product transport's host-key pin or receive a valid signed/native absence response.

This report retains the observed outputs as a narrative only; the disposable overlays were removed after the trial. It is not a signed guest-log bundle. The source is not yet packaged for ordinary installation. No PowerDNS primary/catalog was prepared in this particular fixture, so a successful authenticated parentless deletion proof is still missing. Interrupted installation after SSH receipt/account creation has no automatic cleanup path; revocation disables access but does not remove owner SSH files. A new enrollment after revocation needs an explicit reviewed rotation/cleanup path. Native Debian secondary behavior, wrong-source address enforcement, owner edits, and a full two-direction fault/reboot matrix also remain open. P0.4/P0.5 are not complete.
