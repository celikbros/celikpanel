# Explicit BIND owner enrollment resume (2026-09-28)

D-025 invariants 1-4; P0.4/P0.5. The optional BIND inspector enrollment now exposes `dns-peer-enroll secondary-resume` with the same pair, public-key-file and inspector-file flags as `secondary-install`. It accepts exact staged policy/configuration/binary bytes, reuses a restricted locked `celikpeer` account, and publishes the key only after effective SSH policy and owner files are rechecked. An already authorized exact key returns success only when the whole channel is still configured; an unverified existing channel requires explicit revocation and owner review. A different active key is never replaced. With no authorized key, resume is an explicit owner authorization of the supplied public key, not an automatic key rotation.

The existing `celikpanel-bind-peer-sshd-include/v1` original/receipt contract recognizes backup-only, receipt-before-rename and published-file checkpoints. Only the original bytes or exact recorded publication are admitted. Owner edits and unsupported file metadata stop that operation without overwriting the evidence. Existing accounts require canonical nonzero UID/GID, the reserved primary group, no supplementary groups, the exact home/shell and a locked password. No schema migration, native DNS change, installed-panel update or release publication was performed.

Focused package tests cover those checkpoint states, malformed receipts, owner edits, unrecorded publication, unsafe account identities and unexpected groups. On a fresh disposable Arch guest with native BIND and OpenSSH, the explicitly tagged `TestNativeOwnerEnrollmentResume` passed in 0.44 seconds. It materialized a backup-only checkpoint, completed the SSH publication, then resumed with no account yet present. The resulting channel was configured. Repeating resume preserved the same key. Explicit revocation followed by resume reused the locked account. An appended owner comment in sshd_config caused resume to refuse, and the exact edited bytes survived. The test revoked its key and observed BIND still active. These are materialized interruption states; no actual SIGKILL or power-loss claim is made for this trial.

A final source review added the reserved primary-group check. The rebuilt ordinary CLI was then run on the same guest's owner-edited state: account checks passed, SSH drift was refused, and the before/after sshd_config SHA-256 stayed `9909b9e59e0be38faa9d4679a94407478090722cf2d7a2762d562a2be2fde2c3`. The [captured output](owner-edit-refusal.txt) includes PowerShell's stderr wrapper for the expected refusal. `celikpeer` had only group 969, BIND remained active and status reported the key disabled. The full successful checkpoint trial predates that last additional group check; the rebuilt CLI exercised the stricter check before its expected owner-edit refusal. The native test source is [retained](../../../../../internal/dnspeerenrollowner/secondary_resume_native_linux_test.go).

This closes explicit continuation for the reviewed staged enrollment path in source and the tested Arch checkpoints. It does not prove every crash boundary, native Debian enrollment, concurrent owner edits, coordinated key rotation, removal/cleanup of owner SSH files, product packaging, general paired-primary admission or independent DNS inverse. Earlier enrollment reports retain their historical limitations. The disposable cell was stopped and removed after evidence capture; retained evidence is listed in SHA256SUMS.
