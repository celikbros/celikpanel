# Owner-enrolled parentless deletion: PowerDNS primary / BIND secondary (2026-09-28)

Scope: D-025 invariants 1-4, P0.4/P0.5. A disposable Debian 13 PowerDNS 4.9 primary (`192.0.2.10`) and panel-free Arch BIND secondary (`192.0.2.11`) ran in `pdns-switch__intent__after-write__paired-primary__peer-reachable`. The primary used the test-tagged fresh V3 switch; the public paired-primary setup/RPC gate remained closed. No installed server, release, or owner production DNS was changed. Guest binaries were local and unsigned.

The owner enrollment CLI created a root-only primary Ed25519 credential and installed a source-IP-restricted fixed-command SSH inspector on the secondary. The primary pinned the secondary Ed25519 host-key digest `2b687814d29f6050b0ce38e27f2debf211586657a220a80fabd28b6defff1ad6`. After native AXFR, the product transport made an authenticated read-only challenge: catalog serial `1790605417`, member `s1-kill.test` present, native zone loaded. This exposed two legitimate PowerDNS/BIND representation differences: PowerDNS emits catalog TXT/PTR with TTL 0 and a 32-character base32hex member label, while the BIND producer uses TTL 60 and its own deterministic label; BIND's canonical secondary config can also contain a `file` directive. The inspector parser now accepts those exact alternatives, keeps the catalog envelope/source/uniqueness checks, and rejects malformed labels or mixed metadata TTLs. Focused tests cover the accepted and rejected forms.

A separate root-owned, mode `0600`, scenario/boot/machine-bound authorization permitted one parentless V3 deletion request, `4f722ec8ff34283d19f8514c07654dd3`. The tagged Agent test invoked the actual `SyncDNSZoneV3` path once. It returned terminal success after 13.59 seconds; the durable [ledger](primary-ledger.json) records `succeeded`, attempt 1, and the exact `commit/dns-zone-sync/v3/published/...` phase, with no active request. The [V3 engine receipt](primary-engine-state.json) preserves the acquisition identity. An earlier deliberately blocked public-gate probe is retained as a separate failed switch request in the same ledger; it is not this deletion. The exact member disappeared from the transferred catalog, whose native serial advanced to `1790607757`; [RNDC](secondary-zone-status.txt) reported the zone absent from all views. The pinned [post-deletion inspection](post-deletion-inspection.json) reported transferred catalog, member absent, native zone unloaded and authenticated peer identity.

The secondary was rebooted with management units inactive. [Native status](secondary-after-reboot.txt) shows a new boot ID, active BIND and the empty secondary catalog at serial `1790607757`; [the repeated pinned inspection](inspection-after-reboot.json) again reported authenticated absence/unloaded. PowerDNS and BIND served independently of the panel process during the trial. The read-only probe intentionally uses a synthetic challenge and refuses to consume its proof, so its `proof_gate=proof_replayed_or_unrecorded` field is **expected** and cannot be used as a mutation receipt. Only the real Agent request and durable ledger establish deletion completion. For an unknown peer response, the same request must stay pending for reconciliation; an empty DNS answer alone cannot make it succeed or trigger another delete. If optional inspector enrollment is revoked, native AXFR/serving remain independent, but future parentless deletion requires a fresh valid proof or an authoritative parent-negative response.

This closes the specific parentless PowerDNS-primary/BIND-secondary owner-enrolled deletion experiment that the earlier [V3 zone trial](../pdns-v3-zone-20260928/README.md) left pending. It does not complete P0.4/P0.5 or open the public gate. The product CLI and inspector are not yet packaged for ordinary installation; RNDC key preparation on this Arch guest was manual. Interrupted enrollment cleanup/rotation, native Debian secondary, other fault cuts, owner edits, existing managed BIND-primary to PowerDNS migration, independent inverse, installed update recovery and workload independence remain open. There is no artifact schema version change here: the existing V3 engine receipt and `dns-zone-sync/v3` mutation receipt were exercised; the enrollment, request and response remain v1. The exact VM cell will be removed after evidence capture; the retained files are checksummed in [SHA256SUMS](SHA256SUMS).

## Corrections after intake (2026-10-10)

Checksum repair (2026-10-10): the `SHA256SUMS` of this directory had been committed with CR LF line ends, so `sha256sum -c SHA256SUMS` on a Unix system read every file name with a trailing carriage return and reported each listed file as unreadable. Every listed hash was correct: `tr -d '\r' < SHA256SUMS | sha256sum -c` verified all files before the repair. The line ends of the list were changed to LF (the hashes and file names are unchanged; the evidence files themselves, which are CRLF as collected, were not touched). The `README.md` line of the list was regenerated because this paragraph was added to the README.
