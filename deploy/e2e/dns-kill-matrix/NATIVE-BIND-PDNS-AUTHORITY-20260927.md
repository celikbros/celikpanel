# BIND primary / PowerDNS secondary authority witness

This is a bounded P0.4/P0.5 native-service observation under the D-025 owner-independence invariant. It uses disposable QEMU guests, not installed Frankfurt or Boston panels. The fixture adds an opt-in `celikhost.com` zone alongside its existing test zone; no production schema or lifecycle state changed.

Debian 13 BIND at `192.0.2.10` published the zone through the production managed-BIND setup path. A panel-free Arch PowerDNS `CONSUMER` at `192.0.2.11` loaded it as `SLAVE`. Both endpoints returned authoritative `NOERROR` answers over UDP and TCP for the same SOA (serial `2026092701`), apex NS set (`ns1.celikhost.com`, `ns2.celikhost.com`), `frankfurt.celikhost.com A 192.0.2.10`, and `boston.celikhost.com A 192.0.2.11`.

The primary Agent and Panel were disabled and stopped. Both guests rebooted. The read-only witness required changed boot IDs, active and enabled native `named.service` and `pdns.service`, disabled/inactive primary management, no management binaries on the secondary, and the exact native PowerDNS catalog/member and loaded A records. All checks passed; the pre/post authoritative answer maps were identical. Raw observations are [preboot.json](evidence/authority-20260927/preboot.json) (`4fdb28a34ecc6e660d34bf19007e655112bf839027242922b8cd6956c3a937bf`) and [postboot.json](evidence/authority-20260927/postboot.json) (`b35775f8aeea9fd8c378f562c7107e3ec4dc0d758e100ed21ec58835ba89af74`). The guest bundle manifest SHA-256 was `3dc08798d7f7c6e4064558be2d80ab70963e517bf073cd98b6c0a0ba35d4b4ee`.

This proves initial cross-engine zone loading and native serving across reboot for this exact disposable pair. The production pair-readiness check proves catalog transfer and authoritative member SOA serials, while setup separately checks public nameserver host addresses; neither check compares these exact NS/A answer sets. This witness does not test a later record edit/delete transfer, parent delegation inside the fixture, a panel-free primary, other topologies, or installed-panel update and recovery. P0.4 and P0.5 remain open.
