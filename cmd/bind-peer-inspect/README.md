# Optional BIND secondary deletion inspector

The owner-operated `dns-peer-enroll` CLI can install a fixed-command, read-only SSH inspector on a BIND secondary. Standard catalog AXFR and DNS serving do not require this channel. Its only purpose is to let the primary verify native catalog membership and loaded-zone state when a deleted zone has no authoritative parent that can prove absence. An unavailable or inconsistent observation leaves the exact deletion request pending. The inspector does not mutate BIND, consume proof, or make a pending request succeed by itself.

The current Linux adapter supports only a default-view `named.service` with `/usr/sbin/named -f -u bind` on Debian or `/usr/bin/named -f -u named` on Arch. It ties `systemctl`, `/proc`, socket ownership, `named-checkconf -p`, local catalog AXFR and `rndc zonestatus` to the same process and rereads state before responding. The reviewed catalog must be a secondary from the exact primary IP, available through loopback AXFR, and use RFC 9432 version 2. It accepts the constrained managed-BIND TTL-60/deterministic-label producer and the native PowerDNS TTL-0/base32hex-label producer, with exact SOA/NS envelope, serial and unique membership. Explicit views, a different invocation/config source, a missing RNDC control listener or a malformed catalog fail closed. The Arch fixture needed an owner-prepared `/etc/rndc.key`; the enrollment CLI does not create or repair that native prerequisite.

On the secondary, `secondary-install` accepts the independently reviewed primary public key and a reviewed inspector executable. It verifies and publishes root-owned policy, locked `celikpeer` identity, source-address-limited authorized key, exact no-argument sudo rule, fixed-command wrapper and effective sshd settings. `secondary-host-key` reports the local Ed25519 host-key digest for out-of-band review; the primary must pin it when running `primary-activate`. The primary stores a separate root-only key and enrollment record. `primary-status` and `secondary-status` report configured state; neither claims a live proof. Both ends have explicit revoke commands. Revocation does not stop native DNS transfer or serving.

A disposable Debian PowerDNS-primary / Arch BIND-secondary [native trial](../../deploy/e2e/dns-kill-matrix/evidence/pdns-bind-owner-proof-20260928/README.md) exercised owner enrollment, the product's pinned SSH transport, actual parentless V3 deletion, durable terminal receipt, native absence and secondary reboot. This is one bounded acceptance cell, not a production rollout. The public paired-primary setup/RPC gate remains closed. Current source packaging includes both tools and the owner guide in the optional `dns-owner-tools` archive directory; packaging never enrolls a peer. This has not been published as a release. The explicit `secondary-resume` owner action now continues exact staged enrollment; [its Arch trial](../../deploy/e2e/dns-kill-matrix/evidence/owner-bind-resume-20260928/README.md) also preserved an owner SSH edit while refusing continuation. The same materialized resume checkpoints also passed on [native Debian](../../deploy/e2e/dns-kill-matrix/evidence/owner-bind-debian-20260928/README.md), including the stricter reserved-group check and ordinary CLI owner-edit refusal. Remaining crash cuts, cleanup/coordinated rotation, a full Debian peer-proof exchange and independent DNS inverse are still open. No installed panel was updated by this trial.
